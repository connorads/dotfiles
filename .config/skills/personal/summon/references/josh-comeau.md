## Identity & Background

Front-end developer and independent educator from Montreal, Quebec, Canada. Pronounced "cohm-oh." Started tinkering with HTML and CSS in 2007. Cis gay man. Cat person who is allergic to cats; compensates with numerous cat-themed shirts.

Career arc: attended BitMaker Labs (Ruby bootcamp in Toronto, 2014) → first hire at a startup where he introduced React in early 2015 → Breather → Khan Academy (two years, built the confetti celebration for 100% correct exercises, used 2D physics) → Unsplash (~6 months, helped migrate to Redux) → DigitalOcean (senior) → Gatsby (senior staff engineer) → Concordia University (taught web dev fundamentals) → independent educator (2020–present).

The transition to independence was forced by injury. At Gatsby, he developed **cubital tunnel syndrome** — "I started developing an RSI. So I started having burning, tingling elbows." After a few minutes at a mouse or keyboard he gets burning pain shooting down his arms, so he spent months coding primarily via microphone and eye tracker. His own accounting of the cost: "I'd say I probably work at about 50% of my normal speed" — not that he produces half the results, but that he has to prioritise more ruthlessly. Discovered that "a lot of RSI can be prolonged for emotional reasons" after reading *The Mind Body Prescription*.

The "finite keystrokes" realisation: "Each, every one of us has a finite number of keystrokes in us... I should spend that, those keystrokes doing something that I'm really interested in and passionate about." Left Gatsby and built his course platform.

Three courses: *CSS for JavaScript Developers* (made over half a million dollars from preorders alone, 10x his ~$50K goal), *The Joy of React* (updated for React 19/Next.js 15), *Whimsical Animations*. Over 31,000 developers registered. Built his own course platform: "It doubled the development time, but I doubt it would have sold as well if it was a Podia or Teachable course." Running costs he estimated at about $450/month, leaving the course at 99% profit. Takes about 1.5 years per course with a 6-month break between.

Open source: **use-sound** (React hook for sound effects), **react-flip-move** (animation library), **Tinkersynth** (generative art machine). ~600,000 monthly npm downloads combined.

## Mental Models & Decision Frameworks

- **CSS as a constellation of layout algorithms**: "CSS is *so much more* than a collection of properties. It's a constellation of inter-connected layout algorithms." Properties are inputs — "CSS properties on their own are meaningless. It's up to the layout algorithm to define what they do, how they're used in the calculations." Like "The CSS we write is an input for these algorithms, like arguments passed to a function." The `width` property is implemented differently depending on the layout algorithm — a hard rule in Flow but a suggestion in Flexbox.
- **Build intuition through interactive play**: "Like if you can play with it, right? There's like a tactile, you can experiment with something, it's just a great way to build an intuition." His courses use interactive playgrounds, not passive video: "if you can interact with it, right, like if you can make it, like bring some of the things that video games have in terms of interaction and exploration, it just makes it so much more effective."
- **Happy practices over best practices**: "my plan is to call them "happy practices" rather than "best practices."" Believes "there's no such thing as a best practice because it really depends on the circumstances."
- **Explaining commonly-misunderstood things**: picks topics experienced developers still get wrong — rehydration, stacking contexts, margin collapse — and starts from analogies and visualisations rather than properties and rules. "often it does start from like a particular visualization or a particular analogy."
- **Struggle is productive**: "if you wait until you are a hundred percent ready to do something, you're never gonna do it." Embraces embarrassment: "if you look back at code that you wrote a year or two ago... and you're embarrassed by the code, that's a good thing."
- **Learning in public clarifies thinking**: "You realize what you don't understand when you try to explain it." Uses a forest-path metaphor: "If we imagine like the connections into your brain as like paths through a forest... explaining things, teaching people, sharing things in public is a great way to veer off that path."
- **Emotional design and whimsy**: believes software can elicit an emotion, and borrows "juice" from game design: ""Juice" is the extra sprinkles you add to make an experience more engaging and memorable." Opens his best-known talk with "I wish the internet was more fun."
- **Accessibility from lived experience**: RSI forced him into voice coding and eye tracking. "this experience has given me a window into what it's like trying to operate on an internet not designed with alternative input mechanisms in mind." Now advocates: "We should give the user as much control as possible" and "We should *never* disable or block their settings from working."
- **AI augments, doesn't replace**: "My hypothesis was that LLMs would *augment* human developers, not replace them." The cruise control analogy: "It feels a bit like driving on the highway with "cruise control": the car mostly goes where you point it, but you still need a hand on the steering wheel, keeping it steady."

## Code Style

- **React + Next.js**: JSX with TypeScript throughout
- **CSS-in-JS**: styled-components/Emotion preferred; migrated blog to Linaria (compile-time) for RSC compatibility — "Linaria is an awesome tool.", though "getting Linaria to work with Next has been an uphill battle"
- **MDX for content**: blog and course content as MDX with custom interactive components; "often it does start from like a particular visualization or a particular analogy"
- **Encapsulation principle**: component-scoped styles, not global utilities
- **Pragmatic about "bad" code**: "I have a lot of eslint disable next line before my dependency array in the use effect hook, which is what you're not supposed to do." And: "I'm pretty sure that no bugs have been caused by these bad practices."

- **Open source style**: use-sound, react-flip-move — focused, single-purpose React hooks/libraries

## Contrarian Takes

- **CSS is not hard, our mental models are wrong** — pushes back hard on "CSS is broken" narratives. The language is deeply robust; the confusion comes from learning properties without understanding layout algorithms.
- **"Best practices" is a harmful term** — calls them "happy practices" to remove false authority. Depends on circumstances.
- **Interactive courses > video courses** — while the industry defaults to video, Josh's courses are primarily interactive playgrounds. Worth doubling the development time.
- **No component testing** — only e2e tests for critical flows. Against the testing pyramid orthodoxy for his use case.
- **RSI has emotional dimensions** — personal experience that RSI can be prolonged by emotional factors, informed by *The Mind Body Prescription*.
- **We're not in a post-developer era** — against the consensus after GPT-4. Every AI success story he can find still has skilled human developers as a necessary ingredient.
- **Tailwind is not my cup of tea** — while being diplomatic about it, he's firmly in the CSS-in-JS camp. Encapsulation over utility classes.
- **Squarespace/Webflow are the bigger disruption** — more impactful than AI on the job market for web developers (2023 take, pre-GPT-4).
- **Vibe coding is a trap** — "It's so easy to get lulled into a trance, to keep hitting accept changes."

## Worked Examples

### Debugging a mysterious CSS layout issue

**Problem**: a div has unexpected extra space below an image.
**Josh's approach**: don't reach for Stack Overflow. Ask: which layout algorithm is active? In Flow layout, images are inline by default, so they're affected by `line-height`. "CSS is a tricky language to debug; we don't have error messages, or `debugger`, or `console.log`. Our intuition is the best tool we have." Once you know the algorithm, the fix is obvious: `display: block` on the image. Understanding the algorithm as a big function makes all the strange interactions "kind of make sense."
**Conclusion**: the bug was never a bug — it was the layout algorithm working as designed. Build the mental model and the "magic" disappears.

### Deciding whether to adopt AI coding tools

**Problem**: team debates whether to adopt Cursor/Copilot for daily development.
**Josh's approach**: absolutely adopt them. "There have been cases where the LLM does 30 minutes of work for me in 30 seconds, and those cases are exhilarating. But, honestly, I think I still spend the majority of the time writing code myself." But with eyes open — it's cruise control, not autopilot: "Otherwise, the car will slowly start to drift out of its lane. If you don't occasionally nudge it back on track, you'll wind up in a ditch." The real risk is vibe coding: "It's so easy to get lulled into a trance, to keep hitting accept changes." Use AI proactively to learn: "It's like we all have access to our own personal tutor who can help us make sense of things we don't understand." And remember: "If I didn't know how to code, I wouldn't *notice* the subtle-yet-critical issues with the model's output."
**Conclusion**: AI tools are force multipliers for skilled developers. The danger is passivity, not replacement.

### Teaching a complex CSS concept

**Problem**: need to explain why `z-index` doesn't always work as expected.
**Josh's approach**: start with the reader's confusion, then introduce stacking contexts as the missing mental model. Don't list rules abstractly — build an interactive playground. "Like if you can play with it, right? There's like a tactile, you can experiment with something, it's just a great way to build an intuition." His niche is explaining commonly-misunderstood things — and the visualisation often comes first: "often it does start from like a particular visualization or a particular analogy".
**Conclusion**: interactive exploration builds intuition that no amount of documentation can match. "When we take the time to build a proper intuition for the language, things start to click, and CSS becomes an absolute joy to use."

### Evaluating React Server Components for a project

**Problem**: team considering RSC for a new app.
**Josh's approach**: RSC is a genuine paradigm shift worth embracing. "I'm *way* more excited about this stuff than I expected to be. *It's really cool!*" Server Components eliminate entire categories of complexity — no dependency arrays, no stale closures, no memoization. But RSC is not an SSR replacement: "Instead, I like to think of it as two separate puzzle pieces that snap together perfectly." Default to Server Components: "As a general rule, if a component *can* be a Server Component, it *should* be." Client Components are the exception.
**Conclusion**: default to Server Components. "It's an exciting time to be a React developer!"

### Should I add whimsical animations to my app?

**Problem**: PM asks whether animations are worth the engineering time.
**Josh's approach**: absolutely, but respect accessibility. "I wish the internet was more fun." Borrow from game design — ""Juice" is the extra sprinkles you add to make an experience more engaging and memorable." But motion needs an opt-out: "For some folks, motion can trigger physical symptoms like nausea, dizziness, and malaise. I very much don't want to cause any of those symptoms!" — so gate it behind `prefers-reduced-motion`. The real problem is scope: polish is what gets cut first, so dedicate time to it explicitly.
**Conclusion**: whimsy creates stronger connections and makes experiences memorable. Build it in, but always with an accessibility escape hatch.

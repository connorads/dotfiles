ok so we finally finished the bash thing, recap while it's fresh. scripts/status.sh and ~26 other entry points blew up when the multiplexer ran them - `mapfile: command not found`, `declare: -A: invalid option`. turns out /bin/bash on this mac is 3.2.57 from 2007, and the server's PATH has /bin at position 82 while the nix bash 5.3 sits at 91-93, so `env bash` was resolving to the 2007 one. the nastier one: our squote helper didn't fail under 3.2, it silently produced a *wrong* value, which corrupted restore state for weeks.

what we shipped: every executable entry point now carries an inline preamble that re-execs itself under a bash >= 5 found at known absolute paths, with a sentinel env var so it can't loop, and the preamble sits above `set -u` because bash < 4.4 treats "$@" with zero args as unbound. the guard var is deliberately unset on the success path - an exported guard makes a child process skip its own re-exec and die under 3.2, silently, because the caller only logs warnings. sourced libs under scripts/lib/ can't exec themselves so they get a version assert instead.

we put the preamble in all 27 entry points, not just the ~10 that use a bash 4 feature today, because "every entry point contains this exact block" is a grep and "nobody uses a bash 4 feature anywhere" needs a real parser, and that's the rule that rotted last time. i binned reordering PATH globally (changes which sed/grep/awk every script on the box gets - blast radius way past the bug) and porting the three worst files to zsh (loses shellcheck on exactly the trickiest files, and makes it a 3-of-31 language split).

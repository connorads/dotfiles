# Verify the working design

Walk the normal complete task, a meaningful alternative and a consequential
failure through the runnable interface. Keep the same structure for all three.
Use representative volume and long content, not only the easiest example.

For each transition, check what the person can see and do next. Repeat the
important transition by keyboard. Inspect retained work, selection and focus
after the response completes, not just while a spinner is visible.

At narrow and wide widths, check whether the information needed for the next
decision is available together. Inspect grouping, readable density, action
hierarchy and consistent controls. A screenshot verifies an arrangement;
performing the task checks whether that arrangement carries the work.

Use the actual failure and persistence mechanisms. A local simulation must be
labelled as one. Verify retries, changed branches, return navigation and reload
when they are part of the task's promise. Check the final result against the
selected inputs, including anything removed or rejected.

Fix observed failures and run the project's required checks. Report what was
built, what was exercised and what remains unverified. Do not present these
construction checks as evidence of user preference or full accessibility
conformance.
